# 뱅크샐러드 카드 실적 홈 위젯 — 설계 문서

작성일: 2026-10-21
대상 기기: 소유자 본인의 안드로이드 기기
대상 앱: 뱅크샐러드 `com.rainist.banksalad2` (버전 26.41.0, 버전코드 1260)

---

## 1. 의도와 배경 (Why)

사용자는 뱅크샐러드 앱의 '카드 혜택 > 실적 관리' 화면에 나오는 **카드별 월 실적**(사용액, 목표, 달성 여부, 남은 금액)을 앱을 열지 않고 폰 홈 화면에서 바로 확인하고 싶어 한다. 이 숫자를 보려고 매번 앱을 열고 탭을 이동하는 것이 번거롭기 때문이다.

핵심 요구는 두 가지다.
1. 위젯에 표시되는 숫자가 **뱅크샐러드 앱의 값과 정확히 일치**해야 한다.
2. 사용자가 앱을 직접 조작하지 않아도 위젯이 **스스로 최신 값으로 갱신**되어야 한다.

## 2. 조사로 확인된 사실 (Evidence)

실제 기기와 설치된 APK를 읽기 전용으로 조사해 다음을 확인했다. 이 사실들이 아래 설계의 근거다.

- **뱅크샐러드에는 카드 실적 전용 홈 위젯이 없다.** 앱은 여러 위젯(가계부 예산, 송금, 주택청약, 스마트 소비 쿠폰 등)을 제공하지만 카드 실적 진행률을 보여 주는 위젯은 없다. 따라서 직접 만들어야 한다.
- **실적 화면의 숫자는 접근성 뷰 트리에 평문 텍스트로 노출된다.** `uiautomator dump` 결과, 각 카드가 한 노드에 `"<카드명> <사용액> <목표> 실적 달성 <완료|N원 남음>"` 형태로 들어 있었다. 예: `"그린 체크카드 258,500원 30만원 실적 달성 41,500원 남음"`. 화면 캡처 차단(FLAG_SECURE)도 이 화면에는 없다.
- **앱 재진입 시 자체 재인증(PIN/지문)이 없다.** 앱을 강제 종료(`am force-stop`) 후 다시 실행해도 PIN·지문을 묻지 않고 곧장 홈 대시보드(계좌 잔액 포함)가 떴다.
- **앱은 React Native 기반이고, 콜드 스타트에 약 9.5초가 걸린다.** 첫 표시 액티비티는 `.presentation.navigator.RNNavigatorActivity`다. 단, **실적 화면 자체는 WebView(`FullScreenWebViewActivity`)로 렌더된다**(스파이크에서 확인). 참고로 뱅크샐러드가 이미 한 번 떠 있던 상태(warm)에서는 재시작이 약 3초로 짧아졌다.
- **앱이 딥링크를 받아들인다.** 등록된 스킴은 `banksalad://`, 호스트 `banksalad.com`(및 https App Link, airbridge)이다. `banksalad://benefit?tab=benefit`는 실적 화면이 아니라 홈으로 라우팅되었다. 즉 **실적 화면으로 가는 정확한 딥링크 경로는 아직 미확정이며 구현 단계에서 찾아야 한다.**
- **빌드 환경이 이 PC에 갖춰져 있다.** JDK 21, Android SDK(build-tools 35/36, platform android-35/36, platform-tools, adb)가 설치되어 있다. Gradle은 wrapper로 조달한다.

## 3. 접근 방식의 선택 근거

"앱 값과 정확히 일치" 요구 때문에, 숫자를 얻는 방법은 사실상 두 가지로 좁혀졌고 그중 하나를 명시적으로 배제했다.

- **배제함 — 서버 직접 호출**: 앱의 인증 토큰을 흉내 내어 뱅크샐러드 서버에서 실적을 받아오는 방식. 금융 앱의 보안 계층(인증, 기기 바인딩 등)을 건드리게 되어 계정 잠김 위험이 있고, 유지보수도 취약하다. **이 설계는 이 방식을 쓰지 않는다.**
- **채택함 — 화면 읽기(접근성 스크래핑)**: 별도의 위젯 앱이 뱅크샐러드를 잠깐 전면에 띄우고, 안드로이드 접근성 기능으로 실적 화면 글자를 읽은 뒤 닫는다. 보안 계층을 전혀 건드리지 않으며 사람이 눈으로 보는 값과 동일하다.

## 4. 결정된 설계 (How)

### 4.1 산출물

뱅크샐러드와 **완전히 별개인 안드로이드 앱**(이하 '위젯 앱'). 뱅크샐러드 APK는 수정·리패키징하지 않는다. 위젯 앱은 바깥에서 화면을 읽기만 한다. 그래서 뱅크샐러드는 Play 스토어에서 평소대로 업데이트된다.

### 4.2 구성 요소

1. **홈 위젯 (`AppWidgetProvider` + `RemoteViews`)**: 아래 4.4의 A안 레이아웃으로 카드별 실적을 그린다. 저장된 최신 데이터를 표시한다.
2. **접근성 서비스 (`AccessibilityService`)**: 뱅크샐러드가 전면에 떠 있을 때 실적 화면의 노드를 읽어 텍스트를 파싱한다. 딥링크로 바로 못 가면 UI 노드를 눌러 실적 화면까지 이동하는 역할도 한다.
3. **덮개 오버레이 (`SYSTEM_ALERT_WINDOW`, `TYPE_APPLICATION_OVERLAY`)**: 갱신이 도는 동안 '실적 갱신 중…' 불투명 화면으로 뱅크샐러드 화면을 가린다. **덮개를 누르면 갱신을 즉시 중단하고 폰을 바로 쓸 수 있다**(사용자 결정). 급하게 폰을 켠 경우를 위한 탈출구다.
4. **갱신 트리거**: `ACTION_USER_PRESENT`(사용자가 기기 잠금을 직접 해제한 직후) 브로드캐스트를 받는 리시버. 마지막 갱신 시각으로부터 6시간이 지났을 때만 갱신을 1회 시작한다(쿨다운은 `SharedPreferences`에 기록).
5. **수동 갱신**: 위젯을 누르면 즉시 갱신을 시작하고, 뱅크샐러드 실적 화면도 함께 연다.

### 4.3 갱신 동작 순서

1. 트리거 발생(잠금 해제 후 쿨다운 경과, 또는 위젯 탭).
2. 덮개 오버레이를 화면에 올린다.
3. 뱅크샐러드를 실적 화면으로 띄운다(딥링크 우선, 실패 시 런처 실행 후 접근성 UI 네비게이션).
4. 접근성 서비스가 실적 화면 도달을 감지한다(노드에 `"실적 관리"` 또는 `"실적 기간"` 텍스트 존재로 판정).
5. 카드별 노드 텍스트를 파싱해 데이터로 변환하고 저장한다.
6. 뱅크샐러드를 홈으로 보내고(수동 갱신으로 사용자가 실적 화면을 보려던 경우는 예외) 덮개를 내린다.
7. 위젯을 새 데이터와 갱신 시각으로 다시 그린다.

갱신 도중 사용자가 덮개를 누르면, 위 순서를 즉시 중단하고 뱅크샐러드를 홈으로 보낸 뒤 덮개를 내린다. 이때 위젯 값은 이전 것을 유지하고, 다음 조건(잠금 해제 + 쿨다운)에서 다시 시도한다.

### 4.4 위젯 표시 (A안, 사용자 승인)

- 카드마다 한 줄: **카드명 / 진행 막대 / 완료 또는 "N원 남음"**. 뱅크샐러드 원본처럼 **사용액 / 목표(예: 30만원)** 숫자도 함께 표기한다.
- 상단에 실적 기간(예: `10.1~10.31`)을 표시한다.
- **연결된 카드 전부**를 표시하고, 아직 연결되지 않은 카드(조사 당시 '미연결은행'처럼 금액이 `??`로 나오는 항목)는 제외한다.
- 색·형태는 승인된 A안 시안을 따른다(다크 배경, 초록 진행 막대, 완료 강조).
- **마지막 갱신 상태를 표시한다**(사용자 결정). 위젯 한 구석에 '3시간 전 갱신'처럼 마지막 성공 시각을 보여 주고, 갱신이 실패했거나 값이 너무 오래되면(아래 4.7) 그 사실을 알린다. 오래된 값을 최신으로 오인하지 않게 하기 위함이다.

### 4.5 갱신 시점 정책

- 자동 갱신은 **기기 잠금을 직접 해제한 직후에만** 일어난다(보안 잠금은 어떤 앱도 자동 해제할 수 없으므로).
- 동일 사유로, 사용자가 원래 원했던 '심야 23~06시 고정 4회 무인 갱신'은 구현하지 않는다. 실질 갱신은 보통 '아침에 폰을 처음 쓸 때 1회'가 된다. 이 변경은 사용자와 합의되었다.

### 4.6 빌드와 설치

- 이 PC에서 Gradle wrapper로 디버그 APK를 빌드하고 `adb install`로 기기에 설치한다. Play 스토어 배포는 하지 않는다(본인 기기 사이드로드).
- 접근성 권한과 '다른 앱 위에 표시(덮개)' 권한은 설치 후 **사용자가 설정에서 처음 한 번 직접 켠다**(안드로이드가 자동 부여를 막는 권한들이다).

### 4.7 상태·실패·오래됨 처리 (사용자 결정: 상태 표시함)

- 위젯은 **마지막으로 성공한 갱신의 시각**을 저장하고 표시한다(예: '3시간 전 갱신').
- 갱신이 실패하면(진입 실패, 파싱 결과 없음, 타임아웃, 사용자가 덮개로 중단) 위젯 값은 이전 것을 유지하되, 실패했음을 드러낸다.
- 값이 일정 기준보다 오래되면(기본: 마지막 성공이 24시간 초과) '오래됨' 표시를 한다. 기준 시간은 빌더가 조정한다.
- **월 경계 처리**: 위젯은 마지막으로 읽은 실적 기간(예: `10.1~10.31`)을 함께 표시한다. 달이 바뀌어 아직 새 달 값을 못 읽었으면, 기간 표시로 '지난달 값'임이 드러나게 한다.

## 5-0. 구현 순서 — 접근성 차단 검증을 최우선으로

전체 설계는 '상시 켜진 접근성 서비스가 뱅크샐러드 전면 화면을 읽을 수 있다'는 전제 위에 서 있다. 한국 금융 앱은 제3자 접근성 서비스를 탐지해 화면을 가리거나 실행을 거부하는 경우가 있으므로, **본격 구현 전에 이 전제를 작은 스파이크로 먼저 검증한다**(사용자 결정).

- **스파이크 범위(버리는 코드)**: 최소 접근성 서비스 하나만 있는 앱을 빌드·설치하고, 접근성을 켠 상태에서 뱅크샐러드 실적 화면이 (a) 경고·차단 없이 정상 표시되는지, (b) 서비스가 실적 노드 텍스트를 실제로 읽어 내는지 확인한다.
- **통과 기준**: 차단이 없고 텍스트가 읽힌다.
- **실패 시**: 이 설계의 접근 방식을 재검토한다(서비스 탐지 회피는 다루지 않으며, 근본적으로 막히면 요구사항 자체를 사용자와 다시 논의한다).
- 스파이크 코드는 버리는 용도이며, 통과하면 그때 본 구현을 정식으로 시작한다.

**스파이크 결과(2026-10-21): 통과.** 최소 접근성 서비스 앱(`com.spike.probe`)을 빌드·설치하고 접근성을 켠 상태에서 확인했다.
- (1) 뱅크샐러드 홈과 실적 화면 모두 경고·차단·블랭크 없이 정상 표시되었다.
- (2) 접근성 서비스가 실적 화면 텍스트를 그대로 읽어 냈다: `실적 관리 | 실적 기간 : 10.1~10.31 | 샐러드 신용카드 412,300원 30만원 실적 달성 완료 | 그린 체크카드 258,500원 30만원 실적 달성 41,500원 남음 | 여행 체크카드 0원 30만원 실적 달성 300,000원 남음 | …`.
- **추가 관측**: 실적 화면은 `FullScreenWebViewActivity`, 즉 WebView로 렌더된다. 접근성 읽기는 정상 동작하지만, 화면 이동 설계에 영향이 있다(아래 7절 참고).
- 검증 후 테스트 앱을 제거하고 기기 접근성 설정을 원래대로 되돌렸다.

## 5. 목표 / 비목표 / 안티목표

**목표**
- 홈 화면에서 카드별 월 실적을 뱅크샐러드와 동일한 값으로 확인한다.
- 사용자 조작 없이(잠금 해제 후) 자동 갱신하고, 필요 시 위젯 탭으로 즉시 갱신한다.
- 갱신 중 화면 점유를 덮개로 가려 거슬림을 최소화한다.

**비목표(이번 범위 아님)**
- 뱅크샐러드의 다른 데이터(가계부, 자산, 혜택 금액 등) 표시.
- iOS 버전, 다른 기기로의 일반화.
- Play 스토어 배포.

**안티목표(명시적으로 하지 않음 — 하면 실패)**
- 뱅크샐러드 APK 변조·리패키징.
- 서버 API 직접 호출, 인증 토큰 추출·재사용, 보안 계층 우회.
- root 권한 요구.
- 기기 보안 잠금(PIN/패턴/지문)의 자동 해제.

## 6. 제약

- **보안 잠금은 자동 해제 불가** → 갱신은 잠금 해제 이후 시점에만 가능.
- **접근성은 전면 창만 읽음** → 뱅크샐러드를 잠깐 전면에 띄우는 것이 필수. 완전 무점유(백그라운드 전용)는 불가능.
- **콜드 스타트 약 9.5초** → 갱신 1회에 수 초가 걸린다. 뱅크샐러드를 최근 앱에 살려 두면 warm 스타트로 단축될 수 있다.
- **뱅크샐러드 업데이트 의존성** → 실적 화면의 텍스트 배치나 이동 경로가 바뀌면 위젯의 파싱·네비게이션 규칙을 손봐야 한다. 이는 화면 읽기 방식의 알려진 유지보수 비용이다.

## 7. 빌더에게 남기는 구현 결정

아래는 구현자가 실제 기기·코드로 확정할 사항이다.

- **실적 화면 진입 경로 확정**: 실적 화면으로 가는 정확한 딥링크(`banksalad://…`)를 찾거나, 없으면 접근성 UI 네비게이션 시퀀스(홈 → 카드 영역 → '카드 혜택' 탭 → '실적 관리')를 확정한다. 진입 성공은 노드의 `"실적 기간"` 텍스트로 판정한다. **실적 화면이 WebView이므로**, 진입 경로가 웹 URL 기반일 수 있고 접근성 노드 구조도 네이티브와 다를 수 있다. 이를 감안해 경로와 파싱을 확정한다.
- **파싱 규칙**: 카드별 노드 텍스트에서 카드명(공백 포함 가능), 사용액, 목표, 상태(완료/남은 금액)를 안정적으로 분리하는 규칙. 미연결 카드(`??`) 제외.
- **위젯 레이아웃 구현**: `RemoteViews` 제약 하에서 A안을 구현. 카드 개수 가변 처리(예: `RemoteViewsService`/`ListView` 또는 고정 행 + 필요 시 높이 조정). 마지막 갱신 시각·오래됨·실패 표시 영역 포함.
- **카드 스크롤 대응**: 현재 연결 카드는 3개로 한 화면에 모두 보이지만, 카드가 늘어 실적 목록이 한 화면을 넘으면 접근성은 보이는 노드만 읽는다. 이 경우 스크롤하며 누적 수집하는 처리와, 수집 완료 판정을 구현한다.
- **SDK 레벨**: 기기의 실제 안드로이드 버전을 확인해 `minSdk`/`targetSdk`를 정한다.
- **로딩 완료 판정과 타임아웃**: 콜드/웜 스타트 모두에서 실적 화면 렌더 완료를 감지하는 방법과, 실패 시 덮개를 안전하게 내리는 타임아웃·복구 처리.
- **warm 스타트 유지 여부**: 뱅크샐러드를 최근 앱에 유지해 갱신을 빠르게 할지, 매번 콜드로 띄울지 선택.
- **쿨다운 시간(기본 6시간)** 미세 조정.

## 8. 미해결 / 리스크

- 실적 화면 직행 딥링크가 끝내 없으면 접근성 UI 네비게이션에 의존하며, 이는 뱅크샐러드 UI 변경에 더 취약하다.
- 삼성 One UI에서 `ACTION_USER_PRESENT` 직후 다른 앱을 전면으로 올리는 동작, 그리고 오버레이 표시가 최신 OS 백그라운드 실행 제한에 걸리지 않는지 실기 검증이 필요하다.
